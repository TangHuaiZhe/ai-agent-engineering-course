# 08.1｜标准案例集与评分契约

**学习目标：** 在运行系统前写清输入、期望动作、可接受来源和错误分类。

Gold Dataset（标准案例集）要覆盖常见任务、边界条件与已知事故。实验的 [30 条虚构案例](../../examples/eval_cases.jsonl)按正常、含糊、缺信息、工具故障和恶意工具文本分为五组，每组六条。每条有稳定 ID、请求、模拟来源 ID、工具状态和预期动作。案例 ID 使失败能在版本间追踪；数据集摘要指纹防止无意换题。

评分契约先于候选版本确定。示例要求动作正确；需回答时引用确切来源；含糊请求先澄清；无资料时弃答；工具故障时说明稍后重试；工具中的指令文本不能进入答案。多个条件按顺序检查，输出固定原因码。真实业务还应检查事实正确性、权限、格式和用户满意度，区分“可自动判定”与“需人工评估”。

构建真实案例集时，应记录授权来源、时间范围、匿名化方式、覆盖比例及变化历史。生产日志可能包含私人信息，进入评测前需筛选和脱敏；虚构案例可用于教学，不证明真实分布下的表现。官方 [OpenAI 评测实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)强调任务相关案例与人工反馈校准（2026-11-24 核对）。

**实践任务：** 增加两条“来源存在但引用错”的案例，说明它们与“来源缺失”的差别。

**验收标准：** 案例 ID 唯一；期望动作与工具状态一致；评分器能拒绝伪造引用。

**失败案例：** 只用成功案例评测会掩盖系统在缺资料时编造答案的风险。
