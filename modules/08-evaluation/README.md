# Module 08｜评测与可观测性

Agent 系统的“看起来不错”不能代替可复现证据。本模块把任务验收标准、逐例失败、版本对照和执行轨迹连接起来，用 30 条虚构案例演示如何发现总体提升中的局部退化。

## 学习目标

1. 为任务定义可判定的结果与过程指标，构建分层 Gold Dataset（标准案例集）。
2. 对两个版本使用同一案例集做成对回归比较，列出改善、退化和分组结果。
3. 为每次运行建立 Trace（调用轨迹）和 Span（步骤片段），定位路由、工具、合成环节。
4. 区分确定性检查、模型评审和人工审核，识别评审偏差。
5. 报告数据集、版本、评分规则、限制及未覆盖风险。

## 实践与验收

~~~bash
python3 -m examples.evaluation_lab
python3 -m unittest tests.test_evaluation_lab -v
~~~

验收报告应同时展示总分、分类结果、改善与退化案例、评分方法和数据集指纹。实验使用确定性模拟器，没有调用模型；不把 28/30 解释为真实 Agent 的生产成功率，也不把本地耗时当成线上延迟。

## 典型失败

- 仅报告平均分，忽略普通案例退化。
- 案例来自单一模板，不能代表实际任务分布。
- 用同一个模型既生成答案又当唯一评审，没有人工校准。
- 把原始用户请求、工具文本或秘密直接写入轨迹。
- 改了案例集或评分规则，却与旧版本的分数直接比较。
