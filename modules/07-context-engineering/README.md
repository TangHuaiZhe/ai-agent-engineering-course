# Module 07｜上下文工程

长任务的难点不只是上下文窗口是否够大，还包括旧事实、冗余日志和不可信工具文本会不会挤走当前真正需要的信息。本模块用可复现的虚构任务研究信息选择、预算、压缩、来源和可信边界。

## 学习目标

1. 区分稳定指令、当前请求、任务状态、证据和对话历史。
2. 为上下文设置可测量的预算，并区分真实模型 Token（词元）与教学计数。
3. 比较完整历史、最近窗口、结构化摘要加按需检索的关键项保留效果。
4. 处理事实更正、待办完成与来源追踪，防止旧内容污染当前任务。
5. 保证工具结果始终是数据，不会提升为高优先级指令。

## 实践

~~~bash
python3 -m examples.context_budget_lab
python3 -m unittest tests.test_context_budget_lab -v
~~~

示例不依赖模型接口。其计数器统计中文字符与英文词等教学单位，**不是任何模型的真实 Token 计数**；它衡量关键项是否出现在上下文里，**不是模型回答正确率**。

## 验收与失败案例

验收时展示三种策略的预算占用、关键项覆盖、旧事实残留和恶意工具文本的角色。摘要必须保留当前请求、明确约束、未完成待办、最新事实及来源；待办完成后应消失。

常见失败包括：盲目取最近 N 轮导致早期约束丢失；将旧事实与新事实并列且不标记更正；把网页中的“忽略指令”复制为系统指令；把教学近似计数误报为真实 Token 消耗或成本。
