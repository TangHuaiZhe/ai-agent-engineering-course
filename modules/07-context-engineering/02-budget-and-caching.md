# 07.2｜预算、裁剪与缓存

**学习目标：** 估算上下文占用，并能解释预算、真实 Token（词元）和缓存命中的区别。

预算至少要给稳定指令、当前请求、工具定义、证据和输出留空间。只看输入最大窗口不够：输出也占容量；工具结果长度不可预测；多轮任务还会积累旧日志。工程上应在请求前测量、设置上限，并在超限时采取有序裁剪或重新检索。

示例的 `lexical_units()` 将每个汉字、英文单词和标点记作一个**教学近似单位**。它没有调用模型专用 tokenizer（分词器），因此不能换算真实 Token、费用或延迟。对真实服务，应记录该模型实际返回的输入、输出、缓存命中与费用数据，再用同一组任务比较。

Prompt Caching（提示词缓存）复用相同前缀的处理结果；前缀稳定有助于缓存，但命中取决于具体模型和服务条件。缓存主要影响成本或延迟，**不能修复错误、过期或越权的上下文**。不要为了缓存而保留无关历史。当前 API 行为以 [OpenAI 官方缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching) 为准（2026-11-24 核对）。

**实践任务：** 将实验预算从 500 调为 200，记录哪些策略超限；为检索结果单独预留容量，并说明失败时如何退回。

**验收标准：** 报告同时列出占用、是否超限和关键项覆盖；不把教学近似单位写成真实 Token。

**失败案例：** 删除最早的用户约束以“省 Token”，却保留大量近期日志。长度下降了，任务条件也丢了。
