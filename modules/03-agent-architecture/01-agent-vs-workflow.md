# 03.1｜Agent 与 Workflow：什么时候该交出控制权？

## 本讲要解决的问题

“LLM 能调用工具”并不意味着“必须使用 Agent”。系统的核心区别，不是用了多少模型或工具，而是**运行期间谁来决定下一步**。

- **普通程序（Program）**：流程由代码决定；模型可以只是一个可调用的函数。
- **工作流（Workflow）**：预先定义任务的节点及控制流，模型可能参与某个节点的分类、抽取或生成。
- **Agent**：模型（或其它策略决策器）根据目标与执行反馈动态选择下一步，宿主代码限制可选择的动作。
- **RAG**：检索增强生成，是获取知识的技术；可以被程序、Workflow 或 Agent 使用，并非另一种必然排他的架构。

Anthropic 在 Building Effective Agents 一文中也强调了 Workflow 与 Agent 的控制流区别，并建议从最简单可用方案起步。

## 一个小例子：回答“某公司最近三年毛利率怎么变化”

### 方案 A：确定性 Workflow

1. 代码获取三个年度的财报。
2. 解析营业收入、营业成本。
3. 代码计算毛利率 =（收入 - 成本）/ 收入。
4. 模型将固定的计算表格解释成中文。
5. 程序校验引用与数字，输出报告。

如果数据源固定且字段稳定，这个方案更容易调试、评测和复现。这里使用 LLM 并不构成必须采用 Agent 的理由。

### 方案 B：Agent

当任务变成：“找出毛利率变化最大的业务板块，解释异常原因，如果遇到口径变更则搜索并比对附注”：

1. Agent 选择查询哪个年份和业务板块。
2. 发现字段不可比后，动态选择阅读附注或查找其它正式披露。
3. 根据新证据决定是否追加工具调用。
4. 在检索预算耗尽、证据不足或信息冲突时停止并明确标注。

这类开放式调查任务中，**下一步依赖刚刚得到的结果**，因此 Agent 的弹性可能有价值。但弹性意味着额外的模型成本和更复杂的失败模式。

## 如何决策

| 需求特征 | 首选 | 不要忽略的风险 |
|---|---|---|
| 输入格式固定、步骤确定 | 普通代码 / Workflow | 数据结构变更 |
| 要从资料中找到依据 | RAG + 代码或 Workflow | 检索失误与引用错误 |
| 多步操作，分支可事先枚举 | Workflow + 规则路由 | 分支组合爆炸 |
| 开放式调查，下一步依赖中间结果 | 受约束单 Agent | 工具误用、不可复现 |
| 多个独立子任务需同时调查 | Workflow 并行；必要时 Multi-Agent | 并发成本与结果合并 |
| 高风险不可逆操作（支付、删除、交易） | 确定性事务 + 人工审批 | 授权与幂等性 |

**原则：自由度越大，验证与安全成本通常越高。**

## 哪些部分绝对不该由模型“说了算”？

模型可以提出“查询文档”“重试工具”“生成草稿”。下列约束应由宿主系统强制执行：

- 工具白名单、操作权限、审批状态。
- API 参数类型和业务有效性。
- 执行次数、时间、Token 和费用预算。
- 身份认证、数据可见范围、凭证使用。
- 有副作用操作的去重、幂等与事务一致性。

Agent 是控制流中的一个决策者，**不是安全策略的最终裁决者**。

## 思考练习

判断以下需求应该选 Program、Workflow、Agent，还是组合：

1. 定时抓取 10 家公司的财报并计算固定指标。
2. 对研发知识库中的问题返回带引用的答案。
3. 调查移动 App 一个无法稳定复现的 Crash，并动态选择下一个诊断步骤。
4. 根据用户一句话删除某个生产数据库。
5. 审核新闻引用真实性，发现不匹配时继续搜索。

### 自检参考

1. Program / Workflow；2. RAG + 受控生成；3. 单 Agent 可能合适；4. 不能直接给自主删除权限，应使用审批和确定性后端；5. 固定核验流程结合有限次数的 Agent 研究。
