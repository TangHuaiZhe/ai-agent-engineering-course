# Module 06｜工作流编排与恢复

本模块把工具、检索和状态组织成可暂停、可恢复、可审计的任务流程。示例使用虚构资料和 Python 标准库，不调用模型接口。

## 学习目标

1. 用明确的状态与转移设计固定流程，判断何时需要动态决策。
2. 实现路由、并行取证和有上限的评估修订。
3. 在人工审批处暂停，重启后继续执行。
4. 区分 Checkpoint（检查点）、Retry（重试）、Idempotency（幂等）和 Compensation（补偿）。
5. 用失败注入证明恢复行为。

## 实践与验收

~~~bash
python3 -m examples.workflow_lab
python3 -m unittest tests.test_workflow_lab -v
~~~

验收时应能展示：不同请求走不同路由；两项资料并行取回后稳定排序；检索故障留在上一个检查点；审批前没有报告；重启后审批和写入继续；提交后模拟崩溃再恢复只保留一份报告。

## 典型失败

- 把“模型说已经批准”当作审批；审批必须由受信调用方提交并关联运行 ID。
- 先写外部系统、后存检查点；两者之间崩溃可能重复写入。
- 无限评估修订；必须设置上限和失败出口。
- 并行任务共享可变状态；合并时需要明确顺序与冲突规则。
