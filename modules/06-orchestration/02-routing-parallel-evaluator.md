# 06.2｜路由、并行与评估修订

**学习目标：** 识别可以并行的独立任务，并给评估循环设定停止条件。

Routing（路由）按输入选择确定的分支：示例中含“风险”的请求取公司与风险两项模拟资料，否则只取公司资料。路由规则应可测试、可记录；真实系统须处理模糊分类和未知路由，不能把关键词判断当作通用分类器。

Parallelization（并行化）只适合互不依赖的取证步骤。示例用线程池同时取两项资料，再按请求的键顺序合并。完成先后不决定报告顺序。若来源的版本或权限不同，合并前还需做版本、访问控制与冲突检查。

Evaluator–Optimizer（评估器—优化器）把生成与检查分开。示例第一稿没有引用，评估器发现缺少来源 ID 后修订一次；最多两次尝试。真实评估可检查事实、引用、格式和风险，但评估器本身也会出错，需要基于人工标注样本衡量误报和漏报。

**实践任务：** 注入一个只失败一次的风险来源，观察重试次数；再让来源持续失败，验证状态仍停在 `routed`。

**验收标准：** 分支选择正确；并行合并稳定；暂时性错误最多重试一次；评估尝试次数有上限。

**失败案例：** 一个并行子任务失败时仍提交部分证据，会让后续评估误以为资料完整。示例只有全部成功才提交 `gathered` 检查点。
