# 02.1｜LLM 如何工作：从 Token 到上下文窗口

## 一句话心智模型

大语言模型在给定上下文的条件下，对下一个 Token 的分布进行预测，重复这一过程得到输出。训练使其学到语言、知识与推理模式，但生成过程本身**不是对外部世界的实时事实查询**。

## 1. Token 不等于字、词或字符

Tokenization（分词/编码）把文本映射到模型可处理的离散 ID。中文字符、英文单词、数字和标点在不同 tokenizer 下可能拆分成不同数量的 Token。

- 相同字数的文本不一定有相同 Token 数。
- 向上下文插入 JSON / 工具输出也会消耗预算。
- 不要用“字数除以某个常数”作为精确费用计算方式；实际数量应以具体模型的计量接口为准。

## 2. Transformer 与 Attention 的直觉

文本先经 Token Embedding 变成向量表示，再通过多层计算形成上下文相关的表示。Self-Attention 让某位置综合考虑其他可见位置的信息。因果语言模型的生成一般受到因果掩码约束，不能查看尚未生成的未来 Token。

简化信息流：

~~~mermaid
flowchart LR
  A[文本] --> B[Tokenizer / Token ID]
  B --> C[Embedding]
  C --> D[Transformer Blocks]
  D --> E[Next-token logits]
  E --> F[Sampling / Decoding]
  F --> G[输出 Token]
  G -.-> D
~~~

这张图省略位置编码、KV Cache、不同推理阶段的实现细节。**Attention 不等于“能验证事实”**：模型可以在同一上下文中找出关联，却仍可能引用错误事实或给出无依据的结论。

## 3. 训练、推理与检索的区别

- **Pre-training**：使用大规模语料调整模型参数，形成通用能力。
- **Post-training**：如指令微调、偏好优化等，改善执行指令和行为表现。
- **Inference**：给定权重和输入，计算输出。普通 API 对话通常不会直接更新底层权重。
- **Retrieval / RAG**：从外部数据源选择证据并放入上下文；不是重新训练。

## 4. Context Window ≠ Memory

上下文窗口（Context Window）是**某次模型调用可处理的输入/输出容量约束**，而不是无限、可靠的长期记忆。把完整聊天都放入 Prompt 可能增加成本，且在长文本中产生注意力/检索质量问题。

真正的 Agent 需要将事实、任务进度、授权与已完成的副作用保存为外部状态，并按需检索；不要仅依赖对话历史来决定“已写入数据库没有”。

## 5. Temperature、Top-p 与推理

Temperature 改变采样分布的尖锐程度。它**不直接衡量模型的事实正确率**；Temperature 较低通常更稳定，但仍可能稳定地输出错误答案。Top-p 也用于控制候选 Token 的采样集合。部分推理模型会限制或不支持这些参数，应阅读模型具体 API 说明。
