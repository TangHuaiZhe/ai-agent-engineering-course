# Lab 06｜同集评测、回归与轨迹

**对应 Module 08** · 推荐 4–6 小时 · 无模型 API Key，全部资料为虚构模拟数据。

## 目标

用 30 条固定案例比较两个模拟 Agent 版本。报告总分与分组分数、改善与退化案例、评分原因和脱敏轨迹；对关键回归作人工复核。安全注入是本实验的一类案例，完整安全体系留待 Module 09。

## 运行

~~~bash
python3 -m examples.evaluation_lab
python3 -m unittest tests.test_evaluation_lab -v
~~~

案例集在 [eval_cases.jsonl](../examples/eval_cases.jsonl)。程序输出数据集 SHA256 前 12 位，便于确认两版使用同一输入。基线版故意把工具中的恶意文本复制到答案且漏掉引用；候选版修复这一问题，但对 N05/N06 的合法来源过度拒绝。这些都是**教学模拟缺陷**。

## 步骤

1. 检查五组各六条案例的期望动作与工具状态；为每个类别写一句成功定义。
2. 跑基线与候选版，列出总分、分组分数、改善和退化案例。解释为什么 28/30 不能覆盖普通组退化。
3. 打开 I01、N05 的轨迹，沿 `route → tool → compose` 找到导致评分差异的步骤。确认轨迹属性没有原始请求与攻击文本。
4. 伪造一个引用 ID，验证评分器返回 `invalid_citation`；把工具状态改为缺失，确认系统弃答。
5. 新增至少五条案例，包括重复来源、引用存在但与答案不匹配、工具超时、权限拒绝和含糊请求；在评分前冻结期望。
6. 写出发布门槛：哪些类别绝不允许退化，哪些需要人工复核，出现分歧时如何处理。

## 验收

| 项目 | 分值 |
|---|---:|

 同集成对比较和分类指标 | 25 |

 轨迹关联与敏感文本控制 | 20 |
 回归复盘与发布门槛 | 15 |

提交命令、逐例结果、数据集版本、评分规则、两条失败轨迹的脱敏摘要和限制。实验无真实模型，因此分数不是生产成功率；本地耗时不代表线上延迟，也没有真实 Token（词元）或费用数据。
